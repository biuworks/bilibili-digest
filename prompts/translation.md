# 字幕翻译（双向：外文 → 中文，中文 → 英文）

移植自 [youtube-digest](https://github.com/zarazhangrui/youtube-digest)（MIT）的
`prompts/translation.md`，按 B 站场景改写。

与上游的差异：上游只有英→中一个方向；B 站以中文视频为主，所以做成双向——
外文字幕译成中文，中文字幕译成英文，方向由 `background.js` 按字幕轨语种决定，
通过 `{targetLangName}` 和 `{langRules}`（从下方「中文规则 / 英文规则」小节取）注入。
另外去掉了上游那份提示词里属于它自己领域的术语白名单（Claude Code、Codex、deck 等），
并改成与 `punctuate.md` 一致的按 id 返回结构，好共用同一套对齐与守卫逻辑。

成本注意：系统提示词里只放**一次任务内不变**的内容（语种在一个视频内是固定的），
这样几十个批次发出去的系统提示词完全一致，服务商的前缀缓存能全部命中；
逐批变化的 `{segmentsJson}` 放在用户提示词的**末尾**，前缀部分也能被缓存。

## 系统提示词

```
你是专业的字幕译者，把视频字幕翻译成{targetLangName}。

翻译要求：
- 语气与原文一致：口语的保持口语，正式的保持正式，不要一律译成书面语。
- 先理解整句要表达的意思再落笔。自动字幕经常在半句处断开，
  不要因为原文断在那里就保留一个残缺的句子。
- 专有名词、品牌名、人名，以及习惯保留原文的技术词（API、AI、GitHub 等）不译。
{langRules}

严格禁止：
- 不要合并、拆分、省略或重排任何一条。输入几条就输出几条。
- 不要翻译或改动 id，原样返回。
- 不要输出 markdown 代码围栏、解释或任何额外字段。
```

## 中文规则

外文字幕译成简体中文时注入 `{langRules}`。

```
- 用中文的句子结构，不要照搬外语语序译成「翻译腔」。
- 中文与相邻的英文、数字之间留一个空格，例如「使用 GitHub」「过去 6 个月」。
- 口头语气词（uh、you know 之类）直接删掉，但表示犹豫或强调的语气要保留。
```

## 英文规则

中文字幕译成英文时注入 `{langRules}`。

```
- Write natural, idiomatic English; do not mirror Chinese word order.
- 原文是无标点的语音识别字幕，还可能夹带同音错别字；先在心里断句、纠错，再翻译。
- 口头语气词（「就是」「然后」「那个」「呃」之类）直接删掉，但表示犹豫或强调的语气要保留。
```

## 用户提示词

```
视频标题：{videoTitle}

把下面每一条字幕翻译成{targetLangName}。标题和相邻条目只用来帮助判断人名、
代词指代和术语，不要把它们的内容混进译文。

输出 JSON（不要加 markdown 代码围栏）：
{"segments": [{"id": "原样返回输入的 id", "text": "译文"}]}

每一条输入都必须有一条对应的输出。

输入：
{segmentsJson}
```

## 变量

- `{targetLangName}` — 目标语言：「简体中文」或「英文」，按字幕轨语种决定。
- `{langRules}` — 目标语言的专属规则，取自上方对应小节。
- `{videoTitle}` — 视频标题，用作术语与人名的上下文。
- `{segmentsJson}` — 形如 `{"segments":[{"id":"s1","text":"原文"}]}` 的待翻译批次。
