## 1. 当前已上线能力清单

侧边栏四个标签：**字幕 / 概览 / 笔记 / 问答**。内容脚本只注入 `www.bilibili.com/video/*` 与 `/list/*`（播放页与合集播放页）。Chrome 与 Edge 共用同一份 MV3 zip，最低 Chromium 116。

### 1.1 字幕

| 能力 | 现状 |
| --- | --- |
| 数据源 | B 站官方接口三步：`view` → WBI 签名的 `player/wbi/v2` → hdslb 字幕 JSON。不经第三方转写服务。 |
| 登录 | 部分字幕（含 AI 轨）需已登录；扩展未申请 `cookies` 权限，请求靠浏览器同源 Cookie。 |
| 多轨 | 徽章显示语言与来源（人工 / AI）；多轨时下拉切换。缓存按语言区分，避免串轨。 |
| 默认选轨 | 内置优先级：UP 主中文 → AI 中文 → 英文（`subtitleLangPreference`）。设置页**没有**改优先级的 UI，运行时靠侧栏切轨。 |
| 视图 | 原文 / 译文 / 双语。翻译方向按轨语种自动：中文译英、外文译中。 |
| 顺句 | AI 补标点、改同音错别字；不改措辞、不动时间轴。批次进度可停，已完成保留。 |
| 播放联动 | 当前句高亮；点一句跳转；跟丢后有「回到当前句」。 |
| 搜索 / 复制 / 导出 | `/` 搜原文、顺句稿、译文；一键复制；导出 TXT。 |
| 刷新 | 跳过缓存重新拉取。 |
| 分 P | 缓存与学习资料按 `bvid + page` 隔离。 |

字幕阅读**开箱即用**，不需要 API 密钥。顺句与翻译需要 BYOK。

### 1.2 概览 / 章节

| 能力 | 现状 |
| --- | --- |
| 产出 | AI 通读字幕，生成带时间戳的章节 + 金句；金句按时间挂在所属章节下。点章节 / 金句跳转。 |
| 长视频 | 按分段切块并发；块间重叠上下文（默认 400 字，可关）。设置页可调自动 / 较短 / 较长。 |
| 失败策略 | 部分失败仍出结果；可单独「补失败块」；可整份重新生成；生成中可停。 |
| 展示 | 0.4.5：章节标题更醒目，摘要默认折叠，金句更紧凑。 |
| 持久化 | 字幕缓存 30 天 / 最多 20 条 LRU；用户生成过的概览另存为长期学习资料，缓存过期后仍能与笔记重聚。 |
| 划词解释 | 选中字幕术语 →「解释」；结合前后文大白话；浮层贴在选区旁（非独立标签）。 |

### 1.3 问答

对应 `QA-DESIGN.md` Phase 1，已随 0.4.0 上线（设计稿页眉仍写「待评审」，属于文档滞后）。

| 能力 | 现状 |
| --- | --- |
| 入口 | 独立第四标签。未生成概览也能问。 |

## 3. 技术债 / 已知短板

### 3.1 长视频问答（最需要盯住的产品短板）

设计预算写在商店验收清单里：送入 ≤1.2 万字符，输出 ≤300 字。这对 10 分钟内视频足够（阶梯 0 全量）；对课时 / 直播回放是**有意的质量上限**。

短板机制：

1. **检索是词面重叠，不是语义。** 「反向传播」能打中字幕里的「反向传播」；「这个算法怎么更新权重」若用词与字幕不一致，分数会掉。章节加权能补一部分，但前提是用户已经付费生成过概览。
2. **「总结一下」类问题走骨架。** 停用词剥离后得分为 0，只送每块首句。模型被要求依据不足就说未找到——安全，但用户会觉得「问答不会总结长视频」。概览标签其实才是总结入口，产品上没有把这条路径讲清楚。
3. **预算从尾部裁。** 命中若分散在后半段，可能被丢掉。引用区间闸只认**实际送入**的时间范围，后半段结论会变成不可点或整答被替换。
4. **0.4.3 修过「超长视频引用失效」**，说明超长时轴（延续分钟、直播回放四位分钟）已经咬过一次；回归面仍在。
5. **没有检索透明度。** 用户看不见用了哪些块、是否骨架模式，失败时只能换个说法重问。

### 3.2 隐私 / 本地优先约束（既是债，也是护城河）

这些不是「以后再补的功能」，是架构边界；越界等于换产品。

| 约束 | 后果 |
| --- | --- |
| 无开发者后端、无账号、无 `storage.sync` | 换设备只能 JSON 备份；备份还缺问答 |
| 卸载即清 | 必须把导出做成主路径，而不是附属按钮 |
| AI 流量只去用户填写的源；optional permission 按域名申请 | 不能做统一代理、不能预装「官方额度」 |
| 不申请 `cookies` | 字幕可见性完全跟用户是否已在 bilibili.com 登录走 |
| 安装时主机权限仅 B 站三条 | 番剧 / 课堂 / 直播页不在 content_scripts 匹配里；扩页面要改 manifest 并重写权限理由 |
| 明文 HTTP 仅 loopback | 局域网 NAS 上的模型默认进不来 |
| 全逻辑随包分发，禁止远程代码 | 不能按需下发提示词或模型适配器 |
| 商店禁止堆砌服务商名 | 增长文案与设置页预设必须两套口径 |
| 数据离开设备即「收集」 | 即使用户 BYOK，商店仍要披露 Key 与网站内容 |

本地优先做对了的部分：设置与密钥在 `storage.local`；大体量笔记 / 缓存 / 概览 / 问答在扩展源 IndexedDB（页面脚本碰不到）；所有 IDB 读写走 background 消息；渲染纪律禁止 `innerHTML`。

### 3.3 其它工程短板

- **MV3 service worker 生命周期。** 0.3.0 修过「启动阶段异步读存储导致 SW 被回收、字幕全无」。顶层禁止异步仍是硬纪律；新功能若在 import 时读盘会再踩。
- **播放页 DOM 脆弱。** content script 用候选选择器 + 800ms 重注入 + hydration 等待，避免插节点导致播放器重建。B 站改版是持续风险。
- **B 站风控。** WBI 签名；`-352` 需用户先正常打开视频。扩展绑在非公开接口上。
- **双后端存储。** `storage.local`（设置）+ IndexedDB 四仓库；中间经过 schema v2 迁移。备份 schema 仍冻结在「笔记 + 概览」，与运行时四仓库不对齐。
- **非流式 JSON。** 与截断修复、引用闸门、可取消任务配套；换流式等于重做传输层与问答校验。
- **页面覆盖窄。** 只认 `/video/*` 与 `/list/*`。无字幕则整条学习管线停摆（不做本地 ASR，这是正确的隐私选择，但是能力边界）。
- **翻译维度单一。** 方向自动 zh↔en，没有「选学习语言」。
- **文档债。** 主路线图未入库；问答设计稿状态过期；商店短描述未提问答。

## 4. 未来 6～12 个月：值得做 / 慎做 / 别做

判断标准：是否加深「当前这条有字幕的 B 站视频 → 可检索、可跳转、可带走的学习材料」；是否能在 BYOK + 本地优先 + 双商店单一用途里做完。

### 值得做（3～5）

1. **把问答纳入备份，并在学习稿里可选附录问答。**  
   设计稿 Phase 2 已点名；schema 只需加字段并保持旧备份可解析。换机丢失问答与「本地资料可带走」的承诺相反，而且改动面小于新能力。

2. **长视频问答的可解释性 + 检索小步增强（仍零 embedding）。**  
   先显示本次是全量 / 筛选 / 骨架，并允许「先生成概览再问」。检索侧可加：问句同义词不靠模型、提高章节权重、裁剪改为按分数而不是从尾部切。这是在现有 1.2 万字符预算里提质量，不破坏费用模型。

3. **多时间戳笔记（问答与导出的正路）。**  
   设计稿写明：不要把一条多引用回答塞进「单时刻」笔记。让笔记 / Markdown 原生承载多个可点时间戳后，问答「留下」与学习稿才会一致。这是数据模型升级，不是再做一个聊天附件按钮。

4. **导出与卸载逃生的主路径化。**  
   卸载即清是隐私正确，但对学习工具是事故。设置页备份、学习稿、笔记 MD 已经存在；缺的是发现性（空态提示、问答也能带走）和偶发演练。这比新 AI 功能更符合现有用户。

5. **把规划稿入库，并修设计稿状态。**  
   `FEATURE-ROADMAP.local.md` 若仍在作者本机，应收成 `docs/` 并去掉 `.local`，或把 3.x 已交付项改成 changelog。否则下一个盘点还是猜。同步改 `QA-DESIGN.md` 页眉为已交付，避免代理按「待评审」重做问答。

### 慎做（3～5）

1. **多轮追问。**  
   设计稿否决过。要做必须：默认不回喂全文历史、用户能看见将多发出去的字幕、可一键清上下文。否则费用与「字幕外知识」泄漏会一起上来。

2. **流式输出。**  
   体感更好，但当前管线依赖完整 JSON、截断修复、引用闸。流式等于并行维护两套协议；BYOK 各家 SSE 形状还不一致。若做，先限定在解释 / 笔记润色，不要先动问答。

3. **覆盖番剧 / 课堂 / 直播页。**  
   要扩 `host_permissions` 与 content_scripts，商店权限理由与单一用途都要重写；DOM 与字幕接口也不同。用户会要，但对「学习向点播视频」是范围膨胀。

4. **Anki / CSV / 词汇本。**  
   上游 remix 设想，本仓库从未承诺。做导出格式可以很小；做成间隔重复产品会把侧栏从「看这一集」拖成「语言学习系统」。若做，只出文件、不在扩展里当 SRS。

5. **两阶段模型检索或抬高问答字符预算。**  
   能缓解长视频语义召回，但直接打在「零额外费用 / 送入 ≤1.2 万字」的设计钉子上。没有用量数据前不要动预算。

### 别做（3～5）

1. **融合 YouTube（或任何第二视频网站）进同一扩展。**  
   Issue #6 已明确回绝。字幕源、权限、单一用途声明、商店审核口径全部要重做；上游 youtube-digest 已经覆盖该场景。

2. **Embedding / 本地向量库 / 跨视频知识库作为默认能力。**  
   与 BYOK（中转站常无 embedding）和本地优先（向量索引会膨胀、难备份、难卸载）双双冲突。跨视频问答还会把「当前视频」的单一用途撕开。

3. **开发者后端、官方代扣额度、账号体系、分析 SDK、远程下发代码。**  
   隐私政策与商店披露会作废；从「工具」变成「服务」。这是产品身份，不是优化项。

4. **无字幕时的 ASR / 下载音频转写。**  
   流量、权限、审核、本地算力全部越界；本产品的契约是「有官方字幕才工作」。不要用生成字幕去填。

5. **用 `storage.sync` 或浏览器账号同步密钥与笔记。**  
   密钥进同步存储是事故；笔记进同步会撞配额并违背「不使用账号同步」的已披露口径。换设备只走用户主动导出。

---

## 5. 建议的产品北极星

**在用户自己的密钥与本机存储边界内，把当前这条有字幕的 B 站视频，变成可检索、可引用跳转、卸载前能带走的学习材料。**

——侧栏不是通用聊天机器人，也不是跨站知识库；每一次 AI 调用都应能指回字幕里的某一秒，并且不把数据交给开发者。
